# Link-only employers: legal alternative channels (checked 2026-10-10, 18:35–19:15 CEST)

This is not legal advice. Every fetch followed the policy in `enterprise-ats-legal.md` §3: the honest UA `JobscannerBot/0.1 (personal non-commercial job search; respects robots.txt; max 1 req/5s)`, robots.txt checked first (RFC 9309 handling), at most 1 request per 5 s per host, and no retries around 401/403/429/503 or bot walls. Tools: `scripts/polite.py` (fetcher), `scripts/check_channel.py` (one-off channel probe) and `scripts/link_only_channels.py` (re-counts every channel below). Where a "visible total" needed JS, I rendered the public page once in headless Chrome with the same UA and noted that. Rendering does not rate-limit sub-resources, so it was used only for one-off counts.

Verdict legend: **allowed** means a documented or published feed. **Allowed with limits** means sitemap/HTML/JSON-LD on the employer domain, daily, under §3 limits. **Partial** means discovery or fields are incomplete. **Link-only** means link out from a web-search hit and store nothing beyond title + URL.

## Notable findings / corrections

1. **Allegro is not link-only.** `careers.allegro.eu` is a robots-allowed SF Career Site Builder front end for the same SF company (`allegrospz`; pages say "Company: Allegro sp. z o.o."). Its full sitemap covers all 288 visible jobs. `jobs.allegro.eu` only links the legacy `career55.sapsf.eu` host (robots `Disallow: /`), which is why it looked link-only. **Corrects enterprise-ats-legal.md** (summary row "SuccessFactors legacy host" and §4.1 verdict for Allegro), `seed-companies-pl.json` `unsupported_or_unresolved[Allegro]` and the seed-companies.json note.
2. **Oracle CE sitemaps exist.** Per Oracle docs (https://docs.oracle.com/en/cloud/saas/talent-management/faimh/configure-sitemap-for-search-engine-indexing.html): *"All job posting pages are included in the sitemap called jobPostings… A hidden sitemap link in the career site has been added to the header"*. For Nokia it's `/sitemaps/sitemapIndex`. **Corrects** enterprise-ats-legal.md §4.3 ("No sitemap found"). The verdict stays link-only because of the Oracle ToU.
3. **SmartRecruiters robots red flag (affects source-pack.md):** `https://api.smartrecruiters.com/robots.txt` = `User-agent: LinkedInBot / Allow: /v1/companies/` then `User-agent: * / Disallow: /`. A robots-respecting client therefore may not call the documented Posting API. It is a documented public API, and robots.txt is aimed at crawlers, so this is **UNCERTAIN**. Decide policy (follow the docs vs. robots) for the SR boards in `seed-companies.json`. Greenhouse (`Disallow: /embed/` only), Lever (`Allow: /`, `Crawl-delay: 1`) and Workable (`Content-Signal: search=yes, ai-input=yes, ai-train=no`) are fine. `api.ashbyhq.com/robots.txt` returns 401, which per RFC 9309 §2.3.1.3 counts as "unavailable", so access is allowed.
4. **Hidden documented feeds behind widgets:** Callstack's careers page uses the Recruitee widget `career.recruitee.com/api/c/7305/widget/`, whose offers point to the real slug `callstackpl`. Grupa Pracuj's softgarden page publishes `jobs.feed.json` + `llms.txt`. **Discovery tip:** check career pages for `jobs.feed.json`, `llms.txt` and widget XHRs.
5. **Employer-domain bans beat technical access:** Dynatrace's ToU explicitly bans robots/crawlers on all associated sites, so its CSB stays link-only even though robots allows it. Citi (`citigroup.com/global/terms`: *"Unauthorized use of Citigroup's web sites and systems including but not limited to data scraping… is strictly prohibited"*) would also be link-only if added.
6. **PeopleForce** tenants (Packhelp, Brand24) disallow all crawlers in robots.txt. This **corrects** source-pack-pl.md, which called PeopleForce an "HTML list only (UNVERIFIED terms)" source. Use the employer's own listing page, never the PeopleForce host.
7. **Bot walls seen (not bypassed):** allegro.pl (403 "Please enable JS"), revolut.com (403 on every page, including sitemaps and terms), oviva.com (403), HiBob (503), inghubs.pl (no response).

## Per-employer evidence

### Allegro
- `allegro.tech`: robots 404. The homepage's only job link is `https://jobs.allegro.eu`.
- `allegro.pl/praca`: robots allows it (no `praca` rule), but the response was **403** with "Please enable JS…" (bot wall). Stopped.
- `jobs.allegro.eu`: robots 404. `sitemap_index.xml` holds pages, recruitment and recruitment-policies only (no offers). WP REST types have no job type. `/job-offers/` (rendered) links "Browse job offers" → `career55.sapsf.eu/career?career_company=allegrospz…&loginFlowRequired=true`, whose robots is `Disallow: /`, `Allow: /login`.
- **`careers.allegro.eu`** (found via web search: titles "… Job Details | allegrospz"): robots allows `/job/` and `/search/`. `sitemap.xml` has 288 `/job/` URLs (288 unique IDs). `/search/?q=` static HTML says "Showing 1 to 25 of 288 Jobs". Job pages carry microdata `title, datePosted, jobLocation, address, hiringOrganization, description`. Footer: Allegro privacy policy, cookie policy and recruitment privacy policy. **No ToU.** The sitemap includes warehouse/courier roles in CZ/PL, so filter on title/team.

### Nokia
- Rendered `jobs.nokia.com/en/sites/CX_1`: "All Jobs (623)". DOM contains `<sitemap-link><a href="https://jobs.nokia.com/sitemaps/sitemapIndex">`.
- `sitemapIndex` → `jobpostings` (624 `/en/job/{id}?utm_medium=search+engine` URLs) + `careerSitePages`.
- Static job page `/en/job/40292` has `og:title` "Cyber Security Architect". No JSON-LD before rendering.
- Terms: Oracle.com ToU via the "Legal Notices" footer link (quoted in enterprise-ats-legal.md §4.3).

### Codility / Oviva (HiBob)
- Codility: careers page (robots-allowed WordPress) fetches `/wp-json/codility-blocks/v1/careers-jobs`, which returned `{"error":"The jobs could not be fetched due to API error. We are working on it"}`. The rendered page shows no openings. If it recovers, it is an employer-domain endpoint (undocumented, so UNCERTAIN, low rate).
- Oviva: 403 for `/careers/` and all five declared sitemap indexes.

### Revolut
- robots.txt reachable (200, declares `sitemap-index.xml`, allows `/careers/`). Every other request, including `sitemap-index.xml`, returned 403 to the honest UA. Not bypassed. Web search returns `revolut.com/en-PL/careers/position/...` hits (e.g. "Senior/Lead Software Engineer (Data)"), so use link-out.

### Dynatrace
- `careers.dynatrace.com` → `www.dynatrace.com/careers/` (job list JS-rendered). `apply.careers.dynatrace.com` (CSB, company "DynatraceLLC"): robots standard CSB, sitemap 109 = "Showing … of 109". Job pages have microdata incl. `validThrough`.
- ToU (https://www.dynatrace.com/company/trust-center/terms-of-use/, linked in the CSB footer): *"apply to the Dynatrace web site located at www.dynatrace.com and all associated sites… linked to www.dynatrace.com… By using the Site… you agree to be bound"* and *"you may not use any data mining, robots, crawlers, or other data copying or extraction methods in conjunction with the Site"*. Browsewrap (binding effect UNCERTAIN per legal pack §2), but it's an explicit employer ban, so link-only.

### Grupa Pracuj
- `grupapracuj.pl/kariera` returns 404. The current career site is `www.pracujwgp.pl` (search result). It links `https://www.pracujwgp.pl/jobs.feed.json`: `{"@type":"DataFeed","name":"Active job ads","numberOfItems":9,…}`, with items `JobPosting{title,url(skk.erecruiter.pl/Offer.aspx…),datePosted,jobLocation}`.
- `llms.txt`: *"All job postings are available as structured data in a machine-readable feed using the Schema.org JobPosting format."*

- Visible totals for Comarch, EPAM (225 view vs 4,298 sitemap), Revolut, Oviva, Saleor and Billtech are UNVERIFIED or UNCERTAIN as noted.
- Whether the Oracle and Dynatrace browsewrap ToU bind a non-accepting visitor is UNCERTAIN (legal pack §2). I chose link-only to stay conservative.
